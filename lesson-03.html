Инструменты под конкретные операции

Проверка документации 25.10.2026. Функции сверяются в конкретном аккаунте. «Проверено локально» ниже относится только к нашему учебному инструменту, а не к промышленной эксплуатации.

ChatGPT — документ и проверяемый расчёт

Адрес: https://chatgpt.com/ . Откройте новый проект для задачи, добавьте учебные источники и инструкцию. Для записки используйте файлы 01 и 02; для таблицы файл 05 и запрос «Анализ таблицы заявок». Попросите показать код расчёта и вернуть файл, если этот режим доступен. Скачанный файл откройте и сверьте с входом. При недоступной выгрузке сохраните текст по шаблону. Внешний сервис получает переданный ему материал. Корпоративное разрешение не возникает из подписки.

Claude — длинный документ, сравнение и повторяемая процедура

Адрес: https://claude.ai/ . Новый проект или чат, версии договора 03 и 04, запрос «Сравнение договоров». Для своего skill сначала прочитайте contract-diff/SKILL.md. По доступности включите Create and edit files / code execution и загрузите ZIP через Customize → Skills. Для обычного запроса ZIP не нужен. Организационную выдачу навыков проверяет администратор.

Kimi — обработка файлов и аналитическая записка

Адрес: https://www.kimi.com/ . В доступном Agent/Docs/Sheets добавьте учебные входы и соответствующий запрос. Проверьте, что получен открываемый файл, а не только описание ссылки. В режиме Agent skills доступны через / или + по возможностям аккаунта. Собственная процедура готовится через /skill-creator, если доступно. Факт создания таблицы не подтверждает расчёт: используйте проверочные значения из пакета.

Ollama + Open WebUI — локальная модель и рабочее окно

Документация: https://docs.ollama.com/faq и https://docs.openwebui.com/getting-started/quick-start/ . Это вариант для локального прототипа, а не автоматически защищённая корпоративная платформа. Шаблон запуска в «Локальное-окно.md». Здесь Docker отсутствует; этот стенд не развёрнут и не проверен на нашей машине. Понадобятся установка, модель и проверка на оборудовании. Для команды нужны отдельные аккаунты, роли, управление источниками и обслуживание.

faster-whisper — перевод записи в текст внутри выбранной среды

Папка transcriber содержит работающий CLI, зависимости и учебную запись. Python 3.12, локальная модель, запуск по README. На этой машине выполнено распознавание вымышленной записи, сохранён JSON. Ошибка окончания слова показана в лекции. Нет облачного API, разделения по говорящим и автоматической отправки протокола. Для занятия готовит ведущая, сотрудники не устанавливают Python.

Учебный маскировщик — видимая замена выбранных фрагментов

Адрес: https://aiformanagers.ru/masking.html . Все операции над текстом выполняются в браузере. Указать точные строки, заменить, проверить оставшийся контекст, сохранить зашифрованный справочник, вернуть фрагменты в ответ. Логика и браузерный цикл проверены. Это не полноценный поиск всех персональных данных и не корпоративная DLP.

Presidio — компонент обнаружения чувствительных данных для разработчика

Исходный проект: https://github.com/data-privacy-stack/presidio . Библиотеки Analyzer и Anonymizer можно развернуть локально. Начальная установка: pip install presidio-analyzer presidio-anonymizer в отдельной среде. Нужен NLP-движок и модели. Конфигурация по умолчанию английская; для русского адаптируются модель и распознаватели. Проверка на русских реквизитах обязательна. Здесь не установлен и не протестирован; предлагается как следующий технический шаг, а не готовая гарантия обнаружения.

Как выбирать

Для учебного или разрешённого материала используйте уже доступный утверждённый сервис. Закрытый документ направляется в среду, которую компания разрешила для этого класса данных. Смена провайдера, посредник или новое приложение меняют маршрут. Публичные GPT и сторонние skills не выбирают только по названию: проверяют владельца, содержимое, действия и получателей данных.

До загрузки файла

Ответьте на четыре вопроса: чей это материал; что в нём можно раскрыть; кто фактически получает вход и результат; кто разрешает такую обработку. У одного процесса может быть несколько получателей: чат, приложение, модель, OCR, embedding-сервис, журналирование. Условия и правила определяет компания, а не название тарифа.

Синтетические входы из этого комплекта подходят для учебной пробы в разрешённом сервисе. Реальные документы идут по согласованному маршруту. Если статус неизвестен, сначала вопрос владельцу данных. Внутренний интерфейс тоже проверяют: он может обращаться к внешнему API.

Работа с договором и данными

Передавайте необходимый фрагмент, проверяйте вложения, комментарии, скрытые листы и свойства файла. Замена названия компании не скрывает автоматически редкую сделку, цену и условия. Таблица соответствий остаётся отдельно от запроса. Шифрование этого справочника не шифрует тот текст, который модель должна прочитать.

Не храните пароли, API-ключи и реальные исходники в инструкциях, skill, общедоступном GPT или на портале курса. Выдавайте доступ персонально, с минимальными правами и возможностью отзыва. Инструкция в промпте не ограничивает OAuth-права приложения. В первом пилоте можно работать с вручную переданным разрешённым фрагментом.

Внутренний контур

Локальность проверяют для всех обработчиков, включая распознавание, извлечение текста, embeddings и генерацию. Отдельно нужны сетевые ограничения, роли, шифрование хранилища и управление ключами, сроки для исходников/результатов/логов/бэкапов и способ остановки. Сетевой запрет тестируют наблюдением или правилами ОС/сети, а не вопросом к модели «ты работаешь офлайн?».

Контроль результата

Для записки сверяем источники и противоречия. Для договора — пункт и цитату в обеих версиях. Для таблицы — код/формулу, дубли и пропуски. Для расшифровки — имена, суммы, сроки и смысл по записи. Согласование, отправка, публикация и решение о принятии условий остаются у человека.

Прежние ограничения из сценариев Северстали относятся к конкретному контексту и периоду. В этом уроке они служат поводом выяснить собственные правила компании, а не разрешением или универсальным запретом для всех слушателей.

Как подготовить локальное окно: Ollama + Open WebUI

Локальное рабочее окно для документов

Рецепт для самостоятельного прототипа на синтетике. Docker и Ollama на этой машине не установлены; команды ниже сверены с официальными инструкциями, но этот стенд здесь не запускался. Не используйте рецепт как разрешение обрабатывать реальные закрытые файлы.

Подготовка

Вариант: Open WebUI с Ollama в одном контейнере. Модель Qwen3 8B взята как существующий учебный пример, а не как лучший выбор для всех документов. Требования к памяти и скорости проверяют на своей машине; веса нужно скачать заранее. Сотрудники пользуются интерфейсом, подготовкой занимается ответственный.

На машине с установленным Docker откройте отдельную папку. Сгенерируйте секрет локально. Команды для POSIX-shell:

umask 077
python3 -c "import secrets; print('WEBUI_SECRET_KEY=' + secrets.token_urlsafe(48))" > local-ai.env
docker run -d --name course-local-ai -p 127.0.0.1:3000:8080 --env-file local-ai.env -e OLLAMA_NO_CLOUD=1 -v course-ollama:/root/.ollama -v course-webui:/app/backend/data ghcr.io/open-webui/open-webui:ollama
docker exec course-local-ai ollama pull qwen3:8b

Откройте http://127.0.0.1:3000 и создайте собственную учётную запись по интерфейсу. Не отключайте вход. Выберите локальную модель, не внешний API. Передайте маленький синтетический TXT с контрольным фактом и проверьте ответ по нему.

Для работы с файлами отдельно проверьте извлечение текста, embedding-модель и, если включён, reranker. Они тоже должны быть локальными и заранее подготовленными. Обычный чат без файла не проверяет готовность обработки документов.

Изолированный запуск

После подготовки администратор задаёт OFFLINE_MODE=true и HF_HUB_OFFLINE=1 для Open WebUI и OLLAMA_NO_CLOUD=1 для Ollama, перезапускает среду с сохранением томов. Настройки offline управляют отдельными функциями и загрузками. Сеть ограничивается отдельно, с сохранением связности интерфейса, модели и локальных обработчиков.

Для команды ИТ проектирует HTTPS/SSO, роли, права на документы, логи, сроки хранения и резервные копии. Не открывайте порт Ollama в общий интернет. Демо-команда выше привязывает только веб-интерфейс к loopback ноутбука и не создаёт корпоративный сервер.

Приёмка

После перезапуска и блокировки внешнего трафика должны работать локальный чат и новый тестовый файл с контрольным фактом. Проверяйте сетевые события отдельно. Ещё два теста: пользователь не видит чужой документ; отключение или отсутствие модели не включает облачный запасной путь. Исходники, индекс и результаты хранятся с согласованными правами.

Источники: https://docs.openwebui.com/getting-started/quick-start/ ; https://docs.openwebui.com/tutorials/maintenance/offline-mode/ ; https://docs.ollama.com/faq ; https://ollama.com/library/qwen3:8b . Образ в примере плавающий; для рабочего выпуска ИТ фиксирует версию/digest, лицензии и зависимости.

Локальный запуск транскрибатора

Локальный транскрибатор для демонстрации

Распознаёт вымышленную WAV-запись в локальный JSON. Нет внешнего API, UI, почты, генерации протокола и разделения говорящих. Это однопользовательский CLI, а не готовый корпоративный веб-сервис.

Подготовка с интернетом

Выполните в этой папке на машине с Python 3.12. Для Linux ИТ готовит зависимости отдельно под свою платформу. Модель не включена в ZIP (около 141 МиБ на диске в проверенном примере).

python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python prepare_model.py ./model

Сверьте SHA-256 файлов с model-sha256.json. Веса и зависимости переносите в контур по правилам компании. Файл requirements.txt фиксирует две совместимые верхнеуровневые зависимости; для корпоративного выпуска нужен полный lock под целевую платформу с хешами и проверкой уязвимостей. deps-tested-macos.txt фиксирует среду проверенного прогона и не является Linux-lock.

Распознавание

После подготовки доступ в интернет движку не нужен. Вставьте свои локальные пути. Выходного файла ещё не должно быть.

.venv/bin/python transcribe.py --model ./model --input ./учебная-встреча.wav --out ./расшифровка-новая.json

На Windows вызывайте .venv\Scripts\python.exe. Поддержан PCM WAV 16 bit, mono/stereo, 16 / 44,1 / 48 кГц, до 20 МиБ и 300 секунд. Для другой записи сначала нужен одобренный локальный конвертер. Исходный файл не удаляется. JSON содержит открытый текст, храните его с правами исходника.

Движок загружается из локального каталога с local_files_only. Переменные offline отключают загрузку Hub, Python audit hook блокирует socket.connect/getaddrinfo. Это дополнительная программная мера; native-библиотеки и весь компьютер ею не изолируются. Сетевую изоляцию обеспечивает ОС/контейнер/межсетевой экран.

Пакетный Docker, шаблон для ИТ

Образ и модель подготовить заранее. Dockerfile использует CPU. ИТ фиксирует одобренный digest базового образа и полные зависимости. Команды из папки пакета для POSIX-shell:

docker build -t team-asr-demo:1 .
mkdir -p output
# Владелец output должен разрешать запись UID 10001 контейнера.
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --memory 4g --cpus 4 --pids-limit 128 --tmpfs /tmp:rw,noexec,nosuid,size=128m -v "$PWD/model:/models:ro" -v "$PWD:/input:ro" -v "$PWD/output:/output:rw" team-asr-demo:1 --model /models --input /input/учебная-встреча.wav --out /output/расшифровка-новая.json

В рабочем запуске монтируйте узкий каталог конкретного задания вместо всей папки пакета. Здесь нет порта: network none оставляет только loopback внутри контейнера. Веб-интерфейс для команды требует отдельного сервиса и авторизации. Docker на машине автора отсутствует, этот образ здесь не собран и не проверен.

Что проверено

Тесты запускаются python -m unittest discover -p test_transcribe.py. Проверены: валидный WAV, повреждённый заголовок, обрезанный файл, длительность, symlink, неполная модель, запрет перезаписи и доступ к выходному JSON только владельцу в POSIX, блокировка Python-соединения. Отдельно выполнен настоящий ASR-прогон вымышленной русской записи; пример сохранён. Он не доказывает точность на реальных встречах и полноценное отсутствие всего сетевого трафика ОС.

Маскировщик заменяет выбранные фрагменты, шифрует справочник замен и возвращает их в учебный ответ. Цена, сроки и остальной контекст остаются видимы модели. Маскировка не даёт автоматического разрешения на передачу закрытых данных.

Стоимость и проверка пилота

Когда нужны отдельные вложения

Универсальную сумму для команды без размера и требований назвать нельзя. Сначала выберите операцию и разрешённый маршрут, затем получите цены на подходящие лицензии и инфраструктуру. Цифры прежних презентаций не используем как действующий прайс.

Полная стоимость: лицензии/доступы + подготовка и поддержка процедуры + инфраструктура и хранение + интеграция и контроль доступа + проверка результатов и обучение. Локальная модель не означает нулевую стоимость: нужны оборудование, администрирование и оценка качества.

Для расчёта пилота фиксируйте: число сотрудников; повторений в месяц; время без ИИ; подготовку, генерацию, проверку и исправления с ИИ; стоимость рабочего часа; лицензию; инфраструктуру и поддержку. Эффект по времени считается по всей операции. Высвобождённое время не равно автоматически сокращению расходов.

Решение о расширении принимают после проверки качества, доступа и повторяемости. Если новый инструмент добавил больше проверки, чем убрал работы, меняют операцию или инструмент. Сначала одна понятная задача, затем подключение источников и автоматизация по необходимости.

Методика опирается на авторские материалы: «Генеративный ИИ в деле» (6–8), «Практика под базу» (5–9), «ГенИИ отели и медики» (12–20), «Для юристов» (20–23, 29), «ИИ-ассистенты» (9–16), сценарии обучения «Северстали» и программы с запиской УКК. Файлы упражнений созданы для этого урока; они не содержат корпоративных исходников. Пример Nordgold в архиве описывает операцию, но сам по себе не подтверждает результат внедрения.

Проверено локально: синтетическая WAV-запись распознана faster-whisper; результат сохранён с реальной ошибкой распознавания. Маскировщик прошёл тесты шифрования, восстановления и работы с неизвестными токенами. CSV и инвестиционный расчёт проверены check_data.py. Образцы ответов на записку и договор подготовлены автором упражнения; это не результаты одновременного теста всех облачных сервисов.
